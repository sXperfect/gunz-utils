## 1. Goal

Enhance `gunz-utils` with autonomous agent loop and distributed worker execution primitives:
1. Extend `ResourceBudget` in `gunz_utils.limits` with step-based limits and execution bounds.
2. Extend `WorkflowDAG` in `gunz_utils.dag` with asynchronous concurrent branch execution, resource budget integration, and transactional rollback/compensation hooks.
3. Add a unified `GracefulShutdown` coordinator in `gunz_utils.signals` for preemption, SIGINT/SIGTERM handling, and in-flight cleanup.

## 2. Scope

### In Scope

- **Resource Budget Step Limits (`src/gunz_utils/limits.py`)**:
  - `max_steps`: Non-negative upper bound on agent/tool reasoning steps.
  - `consume_steps(amount=1)`: Atomic step tracking and budget validation.
  - `step()`: Context manager for scoped execution steps.
  - Property `remaining_steps`.
- **Async & Resilient Workflow DAG (`src/gunz_utils/dag.py`)**:
  - `WorkflowStage.compensate`: Optional sync/async rollback hook for undoing side effects upon downstream stage failure.
  - `WorkflowDAG.async_execute(...)`: Asynchronous execution supporting both sync and async stage functions.
  - Concurrency control: Executes independent topological branches concurrently, bounded by `concurrency_limit`.
  - Transactional failure handling: When a stage fails, completed stages are compensated in reverse topological completion order, raising `WorkflowExecutionError`.
- **Graceful Shutdown Coordinator (`src/gunz_utils/signals.py`)**:
  - `GracefulShutdown`: Manages termination signals (`SIGINT`, `SIGTERM`), exposes `is_shutting_down`, triggers registered sync/async cleanup hooks in reverse registration order, and bounds cleanup time with a deadline.
- **Unit & Contract Tests**:
  - Comprehensive unit tests in `tests/test_core/test_orchestration.py`.
  - Regression tests for existing `test_dag.py` and `test_signals.py`.
- **Docs & Changelog**:
  - Add changelog fragment.
  - Verify zero-dependency pure Python invariants and contract suites.

### Out of Scope

- Distributed consensus or distributed lock servers (e.g. Raft, ZooKeeper).
- Heavy external workflow orchestrators (Airflow, Celery).
