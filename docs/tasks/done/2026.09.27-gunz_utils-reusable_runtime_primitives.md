# Task: reusable-runtime-primitives

**Date:** 2026-09-27
**Role:** Programmer
**Component:** `gunz_utils`
**Status:** Completed

## 1. Goal

Consolidate dependency-free runtime/testing primitives discovered during the
`gunz-ml` neural-health workstream into `gunz-utils` so other Gunz
repositories can reuse deterministic sampling and pristine-state variant
experiments without depending on ML-specific code.

## 2. Scope

### In Scope

- Deterministic, process-independent named-item sampling based on stable hashes.
- Generic variant-matrix execution from pristine state.
- Numeric metric comparison and directional-improvement evidence helpers.
- Priority-aware bounded retention and typed structural diffs.
- Lightweight structured tracing.
- Structured/directory fingerprints and a content-addressed local store.
- Named lifecycle fault injection and reversible termination handlers.
- Generic execution provenance with explicit environment allowlisting.
- Standards-oriented network URI/TCP helpers.
- Dependency-free bootstrap/paired-effect statistics.
- Immutable disjoint partition manifests.
- Generic name allow/deny access policy.
- Reuse of the existing shared-foundation `ResourceBudget` for count/time budgets.
- Fingerprint-aware workflow DAG execution.
- Generic acyclic provenance graphs.
- Recency-dependent TTL selection and context-aware retry delays for data acquisition consumers.
- Shell-free rsync directory mirroring for shared/local caches.
- Renewable async lease heartbeat coordination shared by crawler/data/agent workers.
- Namespace-first public APIs and focused dependency-free tests.
- Migration design for `gunz-ml` once its runtime dependency policy is explicit.

### Out of Scope

- PyTorch/tensor traversal and cloning.
- Model, optimizer, scheduler, DDP/FSDP or `torch.compile` semantics.
- HealthEvent/Severity retention or evidence-ranking semantics.
- Jacobian/Hessian/Fisher and other numerical ML diagnostics.
- New third-party dependencies or a new `torch` optional extra.
- Moving existing `gunz-utils` benchmark/instrumentation functionality that
  already supersedes equivalent `gunz-ml` helpers.

## 3. Approach

Reuse existing `gunz_utils.hashing`, `gunz_utils.testing`,
`gunz_utils.benchmark.*`, and package export conventions where practical.
Keep new APIs dependency-free and typed. Migration in `gunz-ml` is
incremental so each extraction slice can be reverted independently.
