## 1. Goal
`.github/workflows/ci.yml` currently runs six separate jobs, one per
extra (`core`, `validation`, `project`, `observability`, `stdlib_fallback`,
`secure`). Each runs `python -m unittest discover tests/<dir> -v`.

This is **redundant and slower than necessary**:
- The CI matrix already installs the right extras per job.
- Each job runs only its own subdirectory, so cross-extra tests never
  exercise the public API at once.
- Each `unittest discover` invocation spins up Python again.

A single `pytest` job with per-extra pip installs is simpler, faster,
and catches integration bugs that the per-extra split misses.

## 2. Scope
### In Scope
- Add ONE new `pytest` job that runs the entire test suite with `pytest`
  (no per-extra splitting).
- Job runs on push to `main` and every PR.
- Job installs `.[all]` so every optional extra is present (matches the
  "happy path" — the per-extra jobs remain in the workflow for the
  *missing-deps* case, which we want to keep as a regression net).
- Do **not** delete the existing six per-extra jobs in this task. They
  remain valuable: they prove each tests works *without* the other
  extras (no cross-pollination).

### Out of Scope
- Removing the per-extra `unittest discover` jobs.
- Splitting pytest by extras (e.g. `pytest -m "not secure"`). Could be
  a follow-up if it turns out some tests need isolation.
- Adding coverage reporting (pytest-cov). Separate task.

## 3. Approach
Use the existing `[tool.pytest.ini_options] pythonpath = ["src"]` (added
in `2026.08.06-pyproject-add_pytest_ini_options`) so pytest can resolve
`gunz_utils` without `pip install -e .`. Install `.[all]` so the
production package is on `sys.path` (helps when imports happen via
`import gunz_utils` rather than just `from gunz_utils import …`).

Job structure mirrors the existing `core:` job (top of the file):

```yaml
pytest:
  name: pytest full suite (all extras)
  runs-on: ubuntu-latest
  strategy:
    matrix:
      python-version: ["3.11", "3.12"]
  steps:
    - uses: actions/checkout@v4
    - name: Set up Python ${{ matrix.python-version }}
      uses: actions/setup-python@v5
      with:
        python-version: ${{ matrix.python-version }}
    - name: Install dependencies
      run: |
        python -m pip install --upgrade pip
        pip install pytest
        pip install .[all]
    - name: Run pytest
      run: |
        pytest -v
```

## 6. Notes
- Why `.[all]` instead of `.[validation,project,observability,secure]`?
  Spelling. `.[all]` is already defined in `pyproject.toml:31-36`.
- Why install `pytest` separately? It's not in `dependencies` or any
  extra today (the project tests use it from a dev install). Pinning
  here makes the CI hermetic — the workflow does not assume the runner
  has pytest pre-installed.
- Future improvement (out of scope): replace the six per-extra
  `unittest discover` jobs with one parameterized pytest matrix
  `extras: ["", "validation", "project", ...]`. That single job would
  cover both the full suite and the per-extra isolation. Keeping the
  split here for now to minimize the diff.
