## 1. Goal
`.github/workflows/ci.yml` currently runs `ruff check src tests` and the
six `unittest discover` jobs (one per extras). The mypy gate added in
pyproject.toml (`disallow_untyped_defs`, `warn_return_any`,
`disallow_incomplete_defs`, etc.) is not in the workflow — so type
regressions cannot block merges.

This task adds a dedicated `mypy` job that gates on `Success: no issues
found in 22 source files`.

## 2. Scope
### In Scope
- One new job `mypy` in `.github/workflows/ci.yml` that installs `mypy`
  (and the four heavy third-party stubs/imports configured under
  `[[tool.mypy.overrides]]` so the overrides don't fail with
  `Module not found`).
- The job must run on every push to `main` and every PR.
- Python matrix 3.11 only (matches `requires-python = ">=3.11"`).

### Out of Scope
- Running `mypy --strict` — that would force full Any elimination across
  the ext backends and is a separate follow-up.
- Running `mypy` against `tests/` — out of scope (tests are not in
  `[tool.mypy] files = ["src"]`).

## 3. Approach
- Add a job after the `ruff` job (or alongside it; alphabetical order
  in CI doesn't matter).
- Install `mypy` plus the four heavy third-party deps the config
  already declares in `[[tool.mypy.overrides]]`:
  - `pydantic`
  - `cryptography`
  - `gitpython` (pulls in `git` namespace)
  - `loguru`
- `pip install .` for the package itself (so `mypy_path = "src"` finds
  `gunz_utils`).
- Run `mypy src/gunz_utils`.

Mirror the existing ruff job structure exactly:
```yaml
mypy:
  name: mypy static type check
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@v4
    - name: Set up Python
      uses: actions/setup-python@v5
      with:
        python-version: "3.11"
    - name: Install dependencies
      run: |
        python -m pip install --upgrade pip
        pip install .
        pip install mypy pydantic cryptography gitpython loguru
    - name: Run mypy
      run: |
        mypy src/gunz_utils
```

## 6. Notes
- This job is independent of the other three CI tasks
  (`ci_ruff_format_gate`, `ci_pytest_gate`, `ruff_format_hash_question_conflict`).
- The job installs four heavy deps solely so mypy's overrides don't
  crash with `ModuleNot found`. An alternative would be
  `--explicit-package-bases` or stub files, but those are more work
  than warranted for the marginal CI cost of installing these packages
  (they are already declared as extras in `pyproject.toml`).
- If a future task removes the override block (e.g. moves to `--strict`
  or generates stubs), this job's install step should be updated to
  match.
